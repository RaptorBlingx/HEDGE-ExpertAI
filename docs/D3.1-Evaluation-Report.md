# D3.1 — Evaluation Evidence Register

**Version:** 2.0-draft
**Date:** 2026-07-31
**Status:** gates pending; no production or proposal KPI pass claim

## Superseded result warning

Earlier report revisions measured a 75-item demo catalogue, v1 pseudo-hybrid ranking and internally authored English labels. Those numbers do not validate the v2 system and are retained only in version control as historical experiment results. They must not be cited as proof that the proposal targets were met.

## Required v2 evidence

| Gate | Requirement | Current evidence status |
|---|---|---|
| Retrieval | Primary HitRate@2 ≥70% on at least 50 jointly reviewed primary queries | Pending reviewed labels and run |
| Secondary metrics | P@2, Recall@K, MRR and nDCG reported separately on held-out data | Pending |
| Languages | ≥20 native/paraphrased held-out queries per non-English language | Pending native review |
| NLU | Macro F1 ≥0.90 overall and ≥0.85 per language | 1,600 training examples exist; evaluation pending |
| Explanation | ≥80% human-reviewed claim-to-evidence support, correct order/apps/language | Validation code exists; human labels pending |
| Latency | Average time to first useful recommendation <5s on target node | Early-result SSE exists; load evidence pending |
| Load/soak | 20 concurrent public sessions and 24-hour bounded-growth soak | Pending |
| Freshness | Source revision to searchable ≤2h and ≤24h outer bound | Timestamps exist; authoritative-source evidence pending |
| Security/accessibility | Authorization, rate-limit, injection, log, failure, restore and WCAG tests | Partial; full acceptance pending |

Acceptance, exposure, discovery-time reduction, maintenance-effort reduction, satisfaction and uptime targets remain pending a consented pilot or before-and-after study. Verified impressions/events prevent double counting but do not create evidence by themselves.

## Label governance

Internally authored labels are provisional and must remain visibly distinct from HEDGE-approved labels. Raw per-query results, environment/artifact versions and timestamps must be retained with every report. A report can only mark a gate passed when the corresponding raw evidence is available for review.

See `docs/traceability-matrix.md` and `docs/evaluation-and-testing.md` for the implementation-to-evidence mapping.
